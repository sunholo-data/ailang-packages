Try your real input.

The synthetic 30-minute soak passed. These checks use your microphone and the instrument's normal capture path. Open this guide before recording; changing tabs during capture discards the take.

Open Loop Lab

1. Enable input without recording

Play the four parts. Select Microphone, then choose Enable microphone and respond to the browser's permission prompt. The permission probe immediately stops its stream; it does not create a take. In Timing & feasibility notes, microphone tracks owned should return to 0.

If you deny permission, the instrument should show a clear error and remain usable. Only claim that check when a prompt was actually denied; permission that was already granted does not exercise rejection.

2. Capture privately, then discard

Mute all four parts and wait for program output to read Silent. Select a part. Hold the capture button or hold Space/Enter while that button is focused, and speak for two seconds. The private meter should move while program output stays silent.

Release. A waveform should become ready, with microphone tracks owned back at 0. Choose Discard. The part should retain its active revision and no recording should become audible.

3. Commit explicitly

Capture another short take. Release and choose Commit to next loop. Wait for the selected lane to acknowledge its new active revision, then unmute that part to listen. The take should be heard only through this explicitly committed part.

4. Cancel and release resources

While holding to capture, move keyboard focus with Tab, switch tabs, or switch applications. The take should be discarded and its microphone tracks released. Returning and releasing the key must not publish the discarded take. You should be able to capture again.

With an external microphone, try a device disconnect during capture. A device-ended or device-change event should discard the take. Enable the microphone again after reconnecting. Browser/device behavior varies; record what actually occurred.

Use Stop & reset during capture or preparation. The transport and private input should close. A late permission reply must release its stream rather than starting an old take. If a browser prompt remains open, resolve or dismiss it before requesting the microphone again.

5. Inspect the local report

Open Timing & feasibility notes and choose Show capture lifecycle report after each scenario. Copy the displayed JSON along with the scenario you tried and what you heard. The report contains state, timing, aggregate meter peaks and bounded lifecycle events; it contains no raw samples, microphone labels or device identifiers.

The last-capture meter summary describes only the most recent attempt. A program peak is an observation, not a physical loopback measurement. Zero owned tracks describes this page's streams, not other applications using the device. Checks are user-reported; this page does not automatically mark them passed.
