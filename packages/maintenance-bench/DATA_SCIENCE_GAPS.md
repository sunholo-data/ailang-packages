# Data-science and authoring observations

Observed on clean AILANG v0.54.17, commit `8f58117f265471584176e2aeb45996c2c9822577`, prompt v0.16.7. These are evidence cards for later routing, not automatic compiler/stdlib changes or measured language superiority.

| Finding | Reproduction/evidence | Handling and candidate ownership |
|---|---|---|

The lexical-validation prototype iterated every character in AILANG. A 1,000-row pipeline run took 3,347 ms. Existing native regex operations plus strict per-token checks retained the adversarial tests. Final scale timings include the stronger schema and lineage logic; intervening changes and host load prevent causal attribution to that optimisation alone. These are single-machine measurements, not a language comparison. Timing must be refreshed after implementation changes.

Git commit time versus acceptance time, annotation certainty, artifact identity, censoring and unknown costs are research-method issues, not evidence of a missing language feature. Native records have explicit equality rules; test field comparisons are not a language defect. Maintain this distinction when prioritising roadmap work.

## Foundation sprint follow-up (v0.54.18, prompt v0.16.7)

- `show(record)` is a display representation that can truncate distinct values. Usage identity controls reproduced a collision between receipts with different input counters. Machine identity now uses explicit lossless JSON fields; no new stdlib feature was necessary.
- New named test bodies containing let bindings reproduced the formatter nil-expression error. Putting the same boolean logic in private helper functions and leaving native test/property bodies as helper calls formats and executes correctly. No new formatter waiver was added.
- The lock command deliberately preserves old generation metadata when resolved dependencies are unchanged. To update the declared runtime for this release candidate, the old dependency-free lock was backed up outside the package and regenerated with v0.54.18; actual binary identity is recorded externally. No core change was made.
- Independent review found measurement bugs in the new instrument: source-only fresh tokens missing generated work; plain edit sums exceeding exact JSON count precision; follow-up windows/renames; contradictory card identities; and Python boolean/number equality in external oracles. Each received a targeted control and a package/oracle fix before any model campaign. These are instrument defects, not evidence of AILANG-versus-Python defect prevalence.

The native analysis remains records/lists/maps/strict JSON; no dataframe engine, provider log parser or compiler/stdlib extension was required. Remaining roadmap candidates need profiling/recurrence and a reuse audit, rather than assuming a language feature from one source pattern.
