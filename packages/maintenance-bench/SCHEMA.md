# Data contracts, version 1

The complete executable boundary types are in `types.ail`; strict decoding is in `codec.ail` and `strict_json.ail`. Use the shipped JSON as a full schema example. Every nullable field is required: null means unknown, not zero. Unknown schema/metric definitions, duplicate JSON keys/identities, fractional count lexemes, unsupported states, incomplete required sources and invalid repair chronology are errors.

A `maintenance.snapshot/1` records source/ref, UTC-millisecond cutoff, completeness, timeBasis (`acceptance`, `commit`, `mixed`, `unknown`), hashed raw evidence frames, and episodes. `files` is the observed canonical touch set (or unclassified/derived paths for a noncanonical episode). Each file must have exactly one structured change with status A/M/D/T/R/C/unknown and old/new paths. Facts from acquisition default to uncertain purpose and unknown provenance/authorship. Collectors do not label a bug.

A `maintenance.annotations/1` file holds reviewed episode labels, optional acceptance-time correction, root cause/detection/evidence/artifact role, defect and introducing-episode link, visible round and provenance. A raw Git commit-time snapshot needs reviewed acceptance timestamps for every included row before accepted-exposure analysis. Annotation IDs must exist and be unique. Repair links require same-project/language chronology and a defect/detection timestamp; unresolved cross-project introducing-change maps are refused rather than guessed.

A `maintenance.cohort/1` manifest freezes cutoff, 30/90-day window, project selection, all/agent authorship stratum, required completeness, canonical-only selection, metric version and declared compiler identity. Annotations and source cutoff are part of report identity; changing them creates a new result.

A `maintenance.report/1` preserves source/input digests, cutoff/selection accounting, per-project/language/cluster denominators, censored/unknown counts, confirmed repair versus interception counts, known usage sums/coverage, and optional descriptive comparisons. `canonicalArtifacts` is observed identity count, not distinct path count; `artifacts` exposes touch and repair-touch frequencies with rename paths. File identity before the snapshot and ambiguous same-timestamp event order are not established. Arithmetic sums refuse precision overflow; zero denominators and zero successes remain unavailable. Rejected/abandoned model runs are not inferred from accepted-change history; future lifecycle run streams need their own source protocol.

`maintenance.expectation/1` is an independently specified oracle over top-level accounting and exact unique repo/language/cluster group coverage. Duplicate expected groups cannot substitute for a missing project. Synthetic analytical expected values were hand-specified, not recorded from the package's first output. `maintenance.timing/1` is separate wall-time/environment evidence, never mixed into canonical report bytes.

## Version 2 ledger boundaries

Inputs are count-only JSON documents with explicit nulls, unique keys/IDs and exact numeric lexemes <=2^53-1. Money is decimal TEXT. New object boundaries reject unexpected fields. Full runnable schemas are in `assets/fixtures/ledger/` and `assets/fixtures/usage.receipts.json`; schemas/fields below are new, not reinterpretations of v1 scalars.

| Schema | Boundary |
|---|---|
| maintenance.index/2 | cutoffMs/windowDays/sourceRef, unique selectedIds and exactly one reviewed decision per selected ID |
| maintenance.usage/2 | strict neutral receipts with source/version/digest, provider request/attempt/model/harness/settings, accounting flags, counters and cost provenance |
| maintenance.trajectory/2 | protocol/role/model/harness/settings, fresh-session retention/treatment, declared left/right languages and finite native plans |
| maintenance.runs/2 | one result per trajectory and three scheduled stage rows per trajectory, including never-started/blocked rows |
| maintenance.cards/2 | draft source/oracle/config identities, observed controls, explicit claim/usage coverage, consumers, reuse audit and proposed route |
| maintenance.ledger-report/2 | actual source package/metric series, input digests, declared compiler, scope/role and structured data |

Index decisions: id, excluded, acceptance, acceptedMs, intent, labels, evidence, provenance. Acceptance is reviewed_exact with a known timestamp, or commit_proxy/interval/unknown with null exact time. Ambiguous rows remain unresolved; a reviewed index does not upgrade a commit-timed follow-up frame. Intent includes feature, repair, migration, mechanical, infrastructure, refactor, performance, security, tests_docs, mixed, unknown. Mixed retains at least two underlying labels. Index intent and a later introduced-defect link are independent.

The historical report names index, in-window follow-up, canonical-workload and total-workload counts. File touches follow validated canonical rename/delete/copy history. They are candidates, not defects; a changed file can have unknown intent. Confirmed linked introductions are observed lower-bound counts: source pagination completeness is not full defect ascertainment, and `indexMature-confirmedIntroductions` is never a clean-program count. Git has no complete local-edit/attempt trace.

Receipt null means unreported, including source-zero cache/reasoning without an attestation flag. inclusive/1 subtracts cache buckets; exclusive/1 already has fresh input; legacy-total/1 yields only its raw known scalar. Combined generated output already includes reasoning. Aggregate both `fresh` input and `freshGenerated` input+generation quantities, with known/missing/subtotal/total. Impossible splits, conflicting identities and overflow fail; possible overlapping imports make affected totals unavailable. USD scale6 is exact with no rounding; unsupported precision/currency remains unavailable. Metered, list-price, local and unknown bases do not pool into savings. Parent summaries validate children without charging twice.

Stage states are completed/failed/blocked/invalid/budget_stopped/not_started. Every started row binds its own prior/candidate digest and attempts. One explicit exception records an unsafe, unhashable candidate without fabricating a digest: state invalid, artifactDigest null, visible/oracle not_run, oracleDigest/oracleArtifact null, checkKinds exactly [infrastructure], a matching priorDigest and at least one real attempt. Subsequent stages retain the last actual prior checkpoint. All other started states still require candidate evidence; an oracle verdict binds the declared oracle and actual candidate. Source requirements/native tool hashes are frozen. Visible pass is separate from independent semantic pass. Invalid or never-launched work does not become model failure; failed spend remains. Local edit counts use exact bounded aggregation and never come from commit counts.

Pairs share family/variant/repeat, protocol, model/settings/harness/retention/treatment and stage requirements/oracles. Languages and pinned native tools/starters remain distinct arms. Per-pair provider drift prevents comparative economics. Reports retain unmatched and preparation/infrastructure usage separately from matched-arm deltas. Cost-per-success is unavailable for zero verified successes, unknown outcomes or missing usage identity/cost. Positive dollar ratios are descriptive floats over exact integer micro-unit totals. Headline fresh+generated delta is unavailable if generation is missing; fresh-input diagnostic stays explicitly separate.

Cards accept immutable 40/64-hex source identities and 64-hex oracle/config digests. Changed-candidate reproduction needs distinct before/after identities, successful builds and actual semantic failed/passed controls. Design-ready reproduction drafts additionally require mutation controls, a reuse audit and independent recurrence or an explicit severity exception. These fields are attested claims for review, not a substitute for replay. Economic claims require the bound controlled report and are rejected by the standalone card schema. Existing public cases are development evidence; general remeasurement requires new confirmation cases.
